# 011 — Lobby Host Forward-Only Rotation and AFK Queue Exhaustion Room Destruction

## Status

Accepted (retroactive documentation — behavior implemented in EPIC-2.6+)

## Context

`LobbyService::transferHost()` implements two non-trivial lobby-AFK behaviors
that were incorrectly attributed in code comments to "ADR-007" (which documents
unrelated protocol audit alignment: `afk_warning`, `error.banned`) and to an
unspecified "A7 spec" that does not exist anywhere in the repository.

The behaviors themselves are sound and already covered by integration tests
(`tests/Manual/test_lobby_integration.php` SUITE 5), but they were undocumented
as architectural decisions — violating ANCHOR_RULES.md Rule 7 (No Hidden
Features), especially the room-destruction trigger when the host-candidate
queue is exhausted.

`ANCHOR_CORE.md` Part 1 § Room Destruction Rules listed only three triggers,
while the Lobby AFK Timer section described a fourth (queue exhaustion) —
an internal contradiction.

## Decision

1. **Forward-only host rotation:** When the lobby AFK timer fires,
   `transferHost()` selects the next **untried** active player strictly
   **after** the current host in `drawer_order` (FIFO). A player who already
   held host and timed out is never re-selected while any later untried
   candidate remains.

2. **Queue exhaustion → room destruction:** If no untried active candidate
   exists after the current host's position in `drawer_order` (every seated
   player has been host at least once without `start_game`), the room is
   force-closed via `closeRoomAfkExhausted()`: every remaining player receives
   `player_left` with reason `afk` (existing removal reason from
   ANCHOR_CORE.md Part 1 § Removal Reasons — no new packet or reason), then
   `destroyRoom()` runs. In `waiting` state `total_paid` is always 0, so no
   refund is required.

3. **Registry:** Add this destruction trigger as the fourth bullet in
   `ANCHOR_CORE.md` Part 1 § Room Destruction Rules.

## Rationale

- Prevents infinite ping-pong between two players when more than two are
  seated (the bug that motivated forward-only rotation).
- Ensures a stalled lobby cannot persist forever when every player refuses
  to start the game.
- Reuses existing `player_left` / reason `afk` — no protocol change.

## Consequences

Positive:
- Behavior is traceable to a correct ADR.
- Room Destruction Rules and Lobby AFK Timer section are consistent.

Negative:
- None (documentation-only correction; no runtime change).

## Compatibility

No code, protocol, economy, or timer threshold changes.

## Amendments to other ANCHOR documents

- `ANCHOR_CORE.md` Part 1 § Room Destruction Rules: fourth bullet added.
- `ANCHOR_CORE.md` Part 5 § Lobby AFK Timer: ADR-007 citation replaced with
  ADR-011.
