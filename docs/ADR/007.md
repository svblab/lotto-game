# 007 — Protocol Audit Documentation Alignment (EPIC-11.5)

## Status

Accepted

## Context

EPIC-11.5 (Protocol Audit) static cross-reference
(`test_protocol_completeness.php`) found three documentation gaps:

1. **`afk_warning`** — emitted by `ReconnectService` (EPIC-8.3) but absent
   from `ANCHOR_CORE.md` § Protocol Packet Types and `ANCHOR_PROTOCOL.md`.
2. **`error.banned`** — declared in the Error Packet Codes registry but
   never emitted; the dedicated `banned` packet type covers every
   ban-rejection path (login, reconnect, admin notification).
3. **`admin_stats_data`** — was declared in both docs but unimplemented at
   EPIC-11.5 time; **later implemented** via ADR-023 (`AdminService::handleGetStats`,
   client wiring in `app.js`). Remaining debt is documentation/status reconciliation
   only (TD-1).

## Decision

1. **Register `afk_warning`** in `ANCHOR_CORE.md` § Protocol Packet Types
   and document its JSON shape in `ANCHOR_PROTOCOL.md` § Turn System.
2. **Document `error.banned` as reserved/unused** in `ANCHOR_PROTOCOL.md`
   with a note pointing to the `banned` packet type. The code stays in the
   registry for forward compatibility; no emission site is added.
3. **`admin_stats_data` unchanged in this ADR** — was unimplemented at EPIC-11.5
   time; later implemented via ADR-023. Track documentation reconciliation under
   TD-1 in `docs/ROADMAP.md` / `docs/IMPLEMENTATION_STATUS.md`.

## Consequences

- `test_protocol_completeness.php` no longer warns about `afk_warning`.
- `error.banned` warning remains (declared but unused) with updated
  semantics documented in ADR-007.
- No runtime behavior changes; documentation-only alignment.
