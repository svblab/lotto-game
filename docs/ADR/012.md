# 012 — Progressive Game AFK Strike Windows (30s / 15s / 5s)

## Status

Accepted

## Context

`Constants::gameAfkTurnSeconds()` returned a single fixed duration (default
30s) used for every AFK evaluation — strike 1, strike 2, and strike 3
(removal) all waited the same interval. Dead constants (`GAME_AFK_STRIKE2_SECONDS=45`,
`GAME_AFK_STRIKE3_SECONDS=50`) and unused helper methods hinted at an
abandoned earlier design but were never wired.

Product decision: shorter windows after each prior auto-draw strike, because
the player has already demonstrated inattention this game. This is a **new**
timer threshold policy — ANCHOR_RULES.md Rule 7 requires ADR approval before
implementation.

`auto_draws` semantics (ADR-008 / ANCHOR_CORE Part 5 § Game AFK Timer) are
**unchanged**: reset to 0 on a genuine manual draw; preserved across turns
for the same player.

## Decision

Per-strike inactivity windows, measured from the moment `afk_start` is
(re)armed for the current drawer turn — **not** cumulative across strikes:

| `auto_draws` at turn start | Strike evaluated | Window | Outcome |
|----------------------------|------------------|--------|---------|
| 0 | 1 | 30s | `afk_warning` + auto-draw; `auto_draws → 1` |
| 1 | 2 | 15s | `afk_warning` + auto-draw; `auto_draws → 2` |
| 2 | 3 | 5s | `removePlayerFromGame(..., 'afk')` (no warning packet) |

### API

`Constants::gameAfkStrikeWindowSeconds(int $autoDraws): int` — single lookup
for server tick evaluation and client `turn_seconds` in `your_turn` /
`afk_warning` packets.

### Environment overrides

Per-strike env vars (positive integers only), matching existing naming:

- `LOTTO_GAME_AFK_STRIKE1` (default 30)
- `LOTTO_GAME_AFK_STRIKE2` (default 15)
- `LOTTO_GAME_AFK_STRIKE3` (default 5)

Legacy `LOTTO_GAME_AFK_TURN` / `LOTTO_GAME_AFK_WARN*` are **removed** — no
callers remain after this Epic.

## Anchor document impact

- `ANCHOR_CORE.md` Part 5 § Game AFK Timer — thresholds table updated.
- `ANCHOR_PROTOCOL.md` § `your_turn` / § `afk_warning` — `turn_seconds`
  clarified as the **current strike's** window (additive clarification; no
  protocol version bump).

## Consequences

- Client countdown (`public/js/ui.js`) already uses server `turn_seconds`;
  no client constant changes required.
- `ReconnectService::tickGameAfk()` evaluates timeout against the window for
  the drawer's current `auto_draws`, not a flat 30s.
- Dead Constants helpers removed (Rule 6 hygiene within this Epic scope).
