# 010 — `host_activity_at` Player Field for Lobby AFK Timer

## Status

Accepted

## Context

The lobby AFK timer (`ANCHOR_CORE.md` § Lobby AFK Timer) measures host
inactivity to transfer `host_conn_id` after `LOBBY_HOST_TIMEOUT` (120s).
The implementation used `player.last_action`, which the `ping` handler in
`server.php` updates every ~2.5s for any connected player in a room —
including the lobby host in `waiting` state.

Automatic client keepalive pings therefore reset the lobby AFK countdown
indefinitely while the browser tab stays open, even when the human host
performs no UI interaction. A recent change also re-broadcast
`host_changed` with a refreshed `host_timeout_start` on every host ping,
making the client-side countdown visibly reset.

The in-game AFK timer already follows the correct principle: `ping` updates
`last_action` for connection liveness but does **not** reset `afk_start`
(see comment in `server.php` near the ping handler). Lobby AFK needs the
same separation.

Per `ANCHOR_CORE.md` Part 6 § Naming Registry, a new Player Structure key
requires ADR approval (ANCHOR_RULES.md Rule 7).

## Decision

1. **New Player Structure key:** `host_activity_at` (unix timestamp, int).
   Used exclusively by the Lobby AFK Timer and the `host_timeout_start`
   field in lobby packets. Not updated by `ping`.

2. **Semantics:**
   - `last_action` / `$connection->lastPing` — network/connection liveness
     (watchdog timer, general room activity tracking). `ping` continues to
     update `last_action` as before.
   - `host_activity_at` — genuine lobby host UI interaction. Updated when
     the current host sends any non-`ping` action while the room is in
     `waiting` with ≥2 players, and on host promotion (`promoteLobbyHost`,
     `transferHost`).

3. **Lobby AFK timer check** changes from
   `time() - host.last_action` to `time() - host.host_activity_at`.

4. **`host_timeout_start` in protocol packets** (`room_joined`,
   `player_joined`, `host_changed`) is sourced from `host_activity_at`, not
   `last_action`. Field name unchanged (protocol compatibility).

5. **Remove** `broadcastLobbyAfkSync()` call from the `ping` handler in
   `server.php`. Legitimate re-sync remains on join (3rd+ player) and on
   genuine host activity via `touchLobbyHostActivity()`.

6. **Game AFK timer** — no change. `ping` must not affect `afk_start`.

## Consequences

Positive:
- Lobby AFK timeout fires correctly when the host is connected but inactive.
- Client countdown (`host_timeout_start`) no longer resets on keepalive pings.
- Consistent with the game-AFK ping-immunity pattern.

Negative:
- One new Player Structure field; all `buildPlayerEntry()` paths must
  initialize it.
- `ReconnectService` `reconnect_state` host timeout fields should eventually
  use `host_activity_at` (follow-up if not updated in this Epic).

## Amendments to other ANCHOR documents

- `ANCHOR_CORE.md` Part 1 § Player Structure: add `host_activity_at`.
- `ANCHOR_CORE.md` Part 5 § Lobby AFK Timer: check
  `time() - host.host_activity_at`.
- `ANCHOR_CORE.md` Part 6 § Player Structure Keys: add `host_activity_at`.

## Compatibility

No protocol packet renamed or removed. `host_timeout_start` semantics
corrected (source field changed internally). No economy or timer threshold
changes.
