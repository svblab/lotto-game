# 013 — Last Survivor Payout Excludes AFK-Cascade Wins by an Equally Idle Player

## Status

Accepted

## Context

`ReconnectService::removePlayerFromGame()` declares a `last_survivor` winner whenever
exactly one active player remains during `playing` or `apartment` state — regardless of
**why** the departing player was removed and regardless of the survivor's own AFK history.

After ADR-012 (progressive AFK strike windows: 30s / 15s / **5s**), a two-player game can
end in seconds when the second-to-last player hits strike 3. The sole remaining player
receives the **entire bank** via `finishGame(..., 'last_survivor')` even when they have
never taken a manual action and have themselves accumulated `auto_draws > 0` (they were
equally inactive but were not the drawer being evaluated when the cascade fired).

`ANCHOR_CORE.md § Last Survivor` predates progressive AFK strikes and states only
"Exactly one active player remains → takes entire bank." That wording is literally
satisfied but contradicts the user-facing intent in `GAME_RULES.md` (the survivor
"kept playing" while others left). This is an economy-affecting product decision —
ANCHOR_RULES.md Rule 7 requires ADR approval.

`handleNoSurvivors()` (EPIC-15.1 / EPIC-15.3) already refunds all participants from
`all_players_history` and broadcasts `game_over` with `reason: no_survivors`. No new
payout code path is needed.

## Options Considered

### Option A (chosen) — survivor `auto_draws` gate on AFK-triggered last-survivor

When `count($active) === 1` is about to pay `last_survivor` **and** the triggering
removal's `$reason === 'afk'`, additionally check the survivor's `auto_draws`. If
`auto_draws > 0`, route to `handleNoSurvivors()` instead (treat as zero genuine
survivors). If `auto_draws === 0`, `last_survivor` proceeds unchanged.

**Pros:** Minimal diff; reuses existing per-player `auto_draws` (ADR-008); no new Player
Structure field; no schema change.

**Cons:** Does not catch a survivor with `auto_draws === 0` who never received a turn
before the room emptied (rare in two-player AFK cascade; both players usually cycle
through drawer).

### Option B — require at least one manual `draw_barrel`

Introduce `has_drawn_manually` on the Player Structure; only survivors who drew manually
qualify for `last_survivor`; otherwise refund.

**Pros:** Stricter engagement proof.

**Cons:** New Player Structure key → Naming Registry amendment; more state to maintain;
broader scope than the reported bug.

### Option C — status quo, document only

Ratify current behavior; update anchor and user docs to say last survivor wins regardless
of own AFK status.

**Pros:** No code risk.

**Cons:** Leaves the economy loophole; contradicts player expectations after ADR-012.

## Decision

**Option A.**

### Exact trigger condition

Apply **only** when all of the following hold:

1. `count($active) === 1` after a removal during `playing` or `apartment`.
2. The **just-removed** player's `$reason === 'afk'`.
3. The surviving player's `auto_draws > 0`.

When all three hold → `handleNoSurvivors()` (refund all stakes, `bank = 0`, room
destroyed). Otherwise → existing `finishGame(..., 'last_survivor')`.

### Unchanged removal reasons

Do **not** alter `last_survivor` for removals with reason `disconnect`, `leave`,
`refuse`, `kicked`, or `banned` — the survivor legitimately outlasted opponents who
left for other reasons; their own `auto_draws` is irrelevant in those cases.

### `ApartmentService`

`removePlayerFromApartment()` has no `count($active) === 1` → `last_survivor` branch
(only zero-active → `handleNoSurvivors`). `finishApartment()` last-survivor after
apartment voting is a separate lifecycle event — out of scope.

## Anchor document impact

- `ANCHOR_CORE.md` Part 2 § Last Survivor — add qualifying condition: payout applies
  only if the survivor has **not** accumulated any AFK auto-draws this game when the
  triggering removal reason is `afk`; otherwise treat as § No Survivors.
- `GAME_RULES.md` §6 — clarify Last Survivor vs AFK-cascade refund case.

## Consequences

- Two mutually idle players in a heads-up AFK race no longer produce a bogus bank
  winner; stakes are returned via the existing refund path.
- A genuinely responsive survivor (`auto_draws === 0`) who outlasts an AFK opponent
  still receives the full bank.
- `snapshotRemainingPlayersToHistory()` in `handleNoSurvivors()` must capture the still-
  active survivor for refund when invoked from this new path (verified in tests).
