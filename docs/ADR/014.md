# 014 — Comparative Win-Chance Calculation (moves-to-close, server-side)

## Status

Accepted

## Context

The client displayed a per-player "win chance" percentage in the game UI
(`public/js/ui.js::calcWinChance()` — `round(marked/15*100)` on local masks).
For **opponents**, this value was effectively broken: `onBarrelsDrawn()` only
updates `state.myMasks`; opponent `masks` are set once at `game_started` as
all-`false` (foreign cards never contain numbers per protocol) and never
updated. Opponents therefore always showed ~0%.

A new comparative formula requires move-distance across **all** players. The
client cannot maintain live opponent mask state by design (opponent card numbers
are hidden). The server already tracks every player's live `masks` in
`$room['players']` via `GameService::markNumber()`.

This is an **information-exposure** change: a derived, coarse percentage (not raw
marks or card numbers) is now visible for all players in the room. Opponent card
numbers remain hidden.

## Decision

### Formula (informational only — never affects economy, victory, or state machine)

For each player entry in `$room['players']` (active and disconnected players
still present in the room map; expired-reconnect players are synchronously
removed elsewhere):

1. Per card: `remaining = 15 - count(mask cells === true for that card)`
   `movesNeeded = ceil(remaining / Constants::BARRELS_PER_TURN)`
2. Multi-card players: `bestMoves = min(movesNeeded)` across cards.
3. `weight = 1 / max(bestMoves, 1)`
   If `bestMoves === 0` (card already complete — should be unreachable before
   victory ends the game): log warning, treat as `bestMoves = 1`.
4. `totalWeight = sum(weights)` across included players.
5. `winChancePercent = round(weight / totalWeight * 100)` per player, keyed by
   `username`.

Independent rounding may cause percentages not to sum to exactly 100 — acceptable
(display-only).

### Implementation home

`VictoryService::calculateWinChances()` — pure card/math, no sockets/db/timers.

### Protocol (additive — no version bump)

New field on server → client packets:

```json
"win_chances": {"alice": 42, "bob": 58}
```

| Packet | When included |
|--------|----------------|
| `barrels_drawn` | After masks updated, when game continues (not on victory-ending draw) |
| `reconnect_state` | `status === 'playing'` only |

Not added to `game_started` (uniform at start; low value).

### Explicit non-goals

- Does **not** affect `checkCardVictory`, `calculatePrize`, apartment, AFK, bank,
  coins, or any state transition.
- Does **not** replace the local player's own `#win-chance-value` indicator
  (client keeps `calcWinChance(myMasks)` for self).

## Consequences

- Opponent list shows meaningful comparative win-chance after each draw.
- `VictoryService` gains one new pure method; `GameService` wires it into
  `broadcastBarrelsDrawn()` and exposes passthrough for `ReconnectService`.
- Clients without the field ignore it gracefully (backward compatible).
